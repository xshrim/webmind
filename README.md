# WebMind

WebMind 是一个从零实现的 Manifest V3 Chrome 扩展：它把网页阅读、写作和研究工具放进浏览器侧边栏，同时允许用户连接自己的模型服务和凭证。

项目使用原创名称、界面和代码，功能范围参考同类浏览器 AI 助手的公开工作流，不包含登录、订阅或购买方案。

## 功能

- 侧边栏聊天：网页、选中文本、PDF、YouTube 字幕、图片和搜索结果上下文
- 流式回答、停止生成、Markdown、安全链接渲染、复制回答
- 划词快捷操作：可关闭、直接显示工具栏，或先显示浮点再悬停展开
- 页面右侧快捷工具：打开侧边栏、沉浸翻译、总结摘要、还原页面
- 输入框自动回复：在网页回复框右上角显示小图标，参考当前页面和已有草稿生成简短回复
- 通用输入框替换：支持 `textarea`、`input` 和 `contenteditable`
- 统一工具：总结摘要、通俗解释、自动翻译、PDF/字幕翻译、图片分析、沉浸翻译、写作和学习工具
- 沉浸翻译译文样式：默认、高亮、分割线、引用、模糊、透明，以及下划线、加粗、斜体、浅色效果
- 搜索页模型回答：在主流搜索结果页右侧显示基于 DuckDuckGo 搜索结果的模型回答，并可点“更多”进入侧边栏继续研究
- 内置工具、自定义工具、对话历史；可分别控制划词浮层、侧边栏位和快捷工具启用哪些工具
- 当前正文识别：自动选择一个正文父容器，并把父容器下的段落、列表、表格、代码块等紧凑整体映射为预览 block；支持正文识别规则、框选正文、逐段删除、自动剔除、大模型智能剔除、复制正文和还原正文
- 当前正文候选评分：用于自动选择正文父容器，并在上下文预览面板的当前正文状态显示总分和分项指标；父容器确定后评分不再筛选或删减正文内容
- 侧边栏代码高亮：当前正文、当前页面预览和对话消息中的代码 block 按需进行语法高亮；正文提取会保留网页提供的语言标记，未知语言自动识别，超长代码保持纯文本代码样式
- 悬停释义：使用内置中英文离线词典，支持配置悬停命中词样式为无、高亮或下划线
- 多语言：界面语言和译文语言都可选择自动、简体中文、繁體中文、English、日本語、한국어、Español、Français、Deutsch、Italiano；设置页使用同一行内并排的两个下拉框，所有真实语言选项固定使用对应语言的自称，“自动”仍跟随当前界面语言。九种语言都有完整静态界面词条；西、法、德、意复用同一套英文核心 Prompt 约束，但工具标题、说明、词典字段和模型最终输出均使用所选真实语言
- 引擎配置：OpenAI 兼容接口、Anthropic、Gemini、Ollama
- API 密钥可选择持久保存或只保留到当前浏览器会话
- 设置导出/导入，导出文件默认不包含密钥

## 当前真实默认配置

以下内容以 `src/shared/defaults.ts` 中的 `DEFAULT_SETTINGS` 为准，不代表用户已经保存过的个人配置：

- 默认上下文：`当前正文`（`defaultContextScope: "article"`）。侧边栏打开时会按设置中的默认上下文自动选中；当前可选上下文只有：无上下文、当前页面、当前正文、当前选中。
- 划词浮层：默认关闭；快捷键默认关闭；最少选中字符数为 `2`。
- 贴边菜单：默认关闭。
- 自动回复：默认关闭；单行输入框限制仍默认为开启。
- 悬停释义：默认关闭；快捷键默认关闭；命中词样式默认为无（`hoverDefinitionStyle: "none"`）。
- 图文提取：默认关闭；最小图片尺寸为 `160`。
- 沉浸翻译：双语模式、默认显示样式、文字效果为弱化（`light`）；段落快捷键、当前上下文快捷键、显示模式切换快捷键均默认关闭；自动白名单为空。
- 沉浸阅读：本地优先、原文（译文）模式、无背景高亮；难度为 `3`；段落快捷键和当前上下文快捷键默认关闭；括号外无效果，括号及括号内文字为弱化；自动白名单为空。
- 网页搜索、搜索页模型回答、快捷动作、Chrome 同步：默认关闭。
- 页面上下文默认附带：开启；历史记录上限：`60`。
- 工具使用提问上下文原始语言进行回答：默认关闭；工具默认使用当前界面语言回答。
- 正文识别规则：默认空数组；每条规则包含适配页面地址和 CSS selector，自动识别前会先尝试匹配规则。
- 界面语言和译文语言：自动；主题：跟随系统；模型思考超时：`0`，表示不限制。

“上下文预览”面板会稳定显示。切换到无上下文、当前页面、当前正文或当前选中时，面板图标、上下文名称和预览内容会同步更新，不再因为上下文刷新反复消失。页面划词触发的“当前选中”只是临时上下文覆盖；选区消失后会恢复进入选中前的上下文，而不是强制回到默认上下文。如果用户在选中期间手动切换上下文，则以用户选择为准。切换 Chrome 标签页时会保持当前页面、当前正文或无上下文的下拉框选择，只刷新到新标签对应内容；如果当前模式是当前选中，则读取新标签的选区，新标签有选区时继续保持当前选中，没有选区时才切换到设置中的默认上下文。

侧边栏直接对话和非翻译正文工具把当前页面、正文或选中内容当作参考上下文：发送前会用真实 Chrome 当前活动标签页校验缓存，只有 `tab.id` 和 URL 都匹配时才复用 `pageContext` 或工具传入的 `contextOverride`，否则会重新读取当前标签页再构造模型输入。页面、正文和选中内容优先使用上下文预览中的 Markdown；自定义工具模板中的 `{{text}}` 和 `{{context}}` 会替换为实际上下文，划词浮层工具也会传递选区的富文本内容。翻译工具不同：它把当前上下文当作待翻译原文，必须走翻译保护和专用 prompt，避免把工具模板、标题或 URL 混进译文。当前正文预览提供“自动剔除”和“大模型智能剔除”：前者使用本地 DOM 特征，后者将全部可见正文 block 交给大模型严格分类，只应用经过 ID 校验的删除决策，并重点剔除评论、互动统计、推荐链接、独立引用和其他辅助内容。

通用设置中的“工具使用提问上下文原始语言进行回答”只控制工具回答：开启时会先根据上下文语言标记和实际正文识别具体原始语言，并将其明确写入最终工具提示词；关闭时使用当前界面语言。普通侧边栏输入框对话不受该设置影响；自动翻译、PDF/字幕翻译和代码解释也不应用这条通用约束。工具提示词仅以某种语言书写不算语言要求，只有明确要求使用某种语言回答时才拥有更高优先级。

当前代码中的普通“工具”是轻量提示词能力：`ToolDefinition` 主要包含名称、图标、提示词模板、模型用途和可用入口，自定义工具也沿用这套结构。它不能直接等同于包含脚本、资源、权限、状态和多步骤执行协议的完整 Skill。沉浸翻译、沉浸阅读、正文识别等带 DOM 操作或共享 workflow 的能力属于固定原生功能，目前没有并入普通工具定义；后续若引入 Skill，应把提示词工具作为 Skill 的一种执行类型，而不是直接改名混用。

“框选正文”不是上下文类型。它是“当前正文”上下文中的自定义操作：用户框选后，所选父容器成为当前正文；展开上下文预览面板的当前正文状态后还可以逐段删除、复制正文，或点击“自动剔除”或“大模型智能剔除”清理疑似非正文段落；“还原正文”会恢复自动识别结果。当前正文预览中的可见 block 是工具、自动翻译、沉浸翻译和沉浸阅读的共同处理对象。

当前正文的核心约定是“一个父容器 + 一组 block”：自动识别和手动框选只负责确定父容器，确定后父容器内所有可见内容都属于正文，标题也包括在内。每个 block 对应原始正文中的一个紧凑段落，保留 block 内换行并支持原文定位和翻译写回。自动剔除、大模型智能剔除和手动删除属于明确的正文编辑操作；除此之外不会在已选定父容器后再次隐式筛选内容。

## 生成未打包扩展

```bash
npm install
npm run check
```

构建完成后，未打包扩展目录是：

```text
dist/
```

它包含 `manifest.json`、后台 service worker、网页 content script、侧边栏页面、设置页面和图标。项目不会生成 `.crx` 文件。

## 在 Chrome 中加载

1. 打开 `chrome://extensions`
2. 打开右上角“开发者模式”
3. 点击“加载已解压的扩展程序”
4. 选择项目下的 `dist/` 目录
5. 点击扩展图标打开 WebMind，或在扩展详情中进入“扩展程序选项”
6. 添加一个模型引擎，填写模型 ID、接口地址和凭证

模型接口地址保存时会按域名申请可选网络权限。访问普通网页、搜索页、YouTube 或 PDF 时，Chrome 也可能要求允许当前站点访问。

## 模型配置

### OpenAI 兼容接口

适用于 OpenAI Chat Completions 兼容服务，以及支持同一请求格式的网关、代理和本地服务。接口地址通常填写到 `/v1`，扩展会请求 `/chat/completions`。

### Anthropic

填写 Anthropic API 地址、模型 ID 和 API 密钥。扩展使用 Messages API 的流式请求。

### Gemini

填写 Gemini API 地址、模型 ID 和 API 密钥。密钥通过请求参数传给 Gemini API。

### Ollama

默认地址是 `http://localhost:11434`，不需要 API 密钥。请确认 Ollama 服务允许来自扩展页面的请求，并在下拉框中填写本机已有的模型名。

## 隐私与边界

- 没有账号体系、登录流程、订阅计划或支付代码。
- 对话和设置默认使用 Chrome 扩展本地存储。
- 发送给模型的内容取决于输入区中的上下文选择、搜索开关和用户主动上传的图片。
- API 密钥保存在 Chrome 扩展存储中；“仅本次会话”模式会在浏览器会话结束后清除。
- Chrome 内部页面、扩展商店页面等受限页面不能注入 content script；PDF 通过侧边栏读取原始 PDF 地址。
- 当前版本使用 DuckDuckGo HTML 结果作为无额外搜索密钥的搜索补充来源；搜索页面结构变化时可能需要调整解析器。

### MCP

- 侧边栏底部的 MCP 选项卡支持添加 SSE 和 Streamable HTTP Server，并在保存或刷新时发现其 Tools。
- 对话附件按钮旁的网络图标可以同时启用多个 Server，也可以只勾选某个 Server 的部分工具。发送普通对话时，模型通过原生 tool calling 决定是否调用这些工具，并综合当前上下文和附件继续回答。
- 通用配置中的“MCP 工具执行授权模式”默认是“始终询问”，也可设为“始终拒绝”或“始终允许”。“始终允许”仍只允许本次对话中用户已启用的工具；“始终拒绝”不会执行工具，并会提示原因。
- 在“始终询问”模式中，用户可以选择“本次允许”“本轮允许”“会话允许”或拒绝。本轮授权只在当前模型 tool-calling 链中有效；会话授权只在当前侧边栏会话内有效，不会持久化。
- 审批窗口在 30 秒无响应时自动拒绝，模型会收到未调用原因并继续回答，不会让整轮对话永久等待。
- 每个助手回答下方会显示 MCP 执行记录：实际使用的 Server / Tool，或未调用的原因（全局拒绝、用户拒绝、授权超时）；调用失败也会显示精简错误原因。
- Server 地址、请求头和已发现工具只保存在本机 Chrome local storage，不进入设置同步，也不会写入操作日志。请求头应按密钥处理。
- 当前仅实现 MCP Tools。Resources、Prompts、Sampling、Roots 和 Elicitation 尚未接入；工具返回的图片、音频和资源会以说明文字传回模型，而不是作为多模态附件。
- MCP 只用于普通侧边栏对话；翻译、图片分析、PDF/字幕和其他固定工作流保持原有请求路径。未启用 MCP 时，原有模型流式回答路径不变。
- 每次发现或调用都会建立并关闭一次 MCP 连接，连接和工具调用分别有超时与结果长度上限。实际可用性仍取决于模型提供商是否支持工具调用，以及 Server 的跨域、认证和网络权限配置。

## 最近完成的功能

- 内容脚本和侧边栏的沉浸翻译/沉浸阅读已统一使用共享 workflow：收集全部 block、按视口可见性排序、分批请求、缺失项递归拆批重试、结果校验、顺序化应用、进度记录。首批可视区域 block 会先完成翻译和写回，再并发处理其余内容。
- 当前正文逻辑已重构为“一个父容器 + 一组预览 block”的模型。规则、手动框选和自动 DOM 识别都只负责确定父容器；自动识别会把正文标题纳入正文，并允许 GitHub README、项目主页、长博客等长正文容器胜出，但会限制向外提升范围并惩罚评论、回复、推荐、导航等混入噪声；父容器中的可见段落、列表、表格、代码块等紧凑整体会成为一一可定位的 block。
- 自动正文候选使用可解释的长度、结构、标题、语义容器、文本密度、链接纯度、聚焦度和干净度指标。长正文不会因为单纯字数或段数更多而持续加分；评论、回复、推荐、导航等嵌入区域会降低候选聚焦度和干净度。评分只参与候选父容器排序及当前正文评分展示，不参与选定父容器后的内容筛选。
- “上下文预览”面板保持稳定显示，图标和内容随无上下文、当前页面、当前正文、当前选中切换；页面划词进入“当前选中”属于临时覆盖，选区消失后恢复划词前的上下文。
- 上下文预览面板在当前正文状态下可查看 selector、来源、段数、字数和正文 block；block 支持多行富文本预览，点击时跳转高亮定位，右侧 `X` 图标可从当前正文删除该段。
- 当前正文、当前页面、当前选中预览，以及助手回答和普通用户消息中的 fenced code block 支持语法高亮。DOM 提取除了 `<pre>`，还会识别块级 `<code>`、语言属性，以及带通用 `code`、`source`、`highlight`、`syntax`、`prettyprint` 语义且不包含普通正文结构的代码容器；只选中同一代码容器内的一部分文字时也会保留为 fenced code。提取层会从通用 `language-*`、`lang-*`、`highlight-source-*` class 或 `data-language`/`data-lang` 属性保留语言标记；当前页面预览通过 Markdown lexer 划分顶层 block，不会拆散内部带空行的代码段。预览面板展开时会直接激活共享的本地 `highlight.js`，不再依赖折叠滚动容器中的可见性观察；对话消息仍按可见性懒加载。高亮 HTML 在 Markdown 转换阶段声明式生成，因此父组件重渲染不会清除高亮；展示逻辑不改变正文 block 原文、Markdown、复制内容或翻译写回对象。对话气泡会为 Markdown 的 `<strong>`/`<b>` 启用字重合成并使用 `700` 字重，确保缺少实体粗体字形的中日韩及系统回退字体仍能显示加粗。
- 上下文预览面板在当前正文状态下的复制按钮右侧显示评分数字；评分悬停或键盘聚焦时显示总分和各项指标的统一样式 tooltip。正文发生框选、还原、自动剔除、大模型智能剔除或手动删除 block 后，评分会按当前保留的 block 刷新；评分上升为绿色、下降为红色、无变化使用默认图标色。
- 上下文预览面板在当前正文状态下支持自动剔除、大模型智能剔除、selector 规则保存、“还原正文”“框选正文”和“复制正文”。两个剔除按钮仅显示图标并通过 tooltip 说明；selector 标签可点击弹出规则编辑器，默认填入当前页面地址和 selector；保存后会进入设置页的正文识别规则。
- 设置页新增“正文识别”配置块，位于“工具启用”和“数据同步”之间；“识别规则”列表可添加、编辑、删除适配页面地址和 CSS selector，地址语法与黑白名单类似。
- 正文识别会先按 `articleExtractionRules` 匹配当前 URL 和 selector；匹配不到时再用通用 DOM 候选选择最像正文的父容器，不再使用结构化数据或第三方正文解析来合成正文结果。
- 支持通过感知 HTML 层级的交互框选正文；tooltip 两行显示元素位置/selector 和操作提示；滚轮/方向键调整层级，点击确认，`Esc` 取消且不弹出取消提示；切换 Chrome 标签页时会取消正在框选状态。
- 手动框选正文保留 DOM 来源和精确 CSS selector，不再把来源变成 `manual` selector；手动范围可还原为自动识别正文。
- 当前正文支持 `article`、`main`、开放 Shadow DOM 和同源 iframe 等候选来源；自动翻译、沉浸翻译和沉浸阅读的“当前正文”会使用与上下文预览面板当前正文状态一致的完整 `articlePreview` 可见 block，而不是重新抓取另一套正文。当前正文字段不做长度截断，预览数组也不限制 block 数量。
- 已优化正文识别性能：侧边栏读取上下文采用协作式异步识别，可见文本遍历、候选收集、评分和最终 block 收集会按约 `6ms` 时间片主动让出页面主线程；识别完成前不修改原始网页 DOM，预览定位只记录 block 对应元素。
- 自动正文刷新现在使用可取消的串行扫描：标签切换、页面更新和窗口聚焦产生的新刷新会在下一个协作式 checkpoint 终止旧刷新，同一页面不会再叠加多套异步正文扫描；用户主动执行的正文读取和编辑仍按顺序完整完成。候选评分阶段不再为未选中的父容器生成 Markdown，并在单次扫描内分别缓存含噪和去噪规则下的紧凑后代判断；最终选中正文仍使用原有完整 block、Markdown 和评分逻辑。debug 日志会记录正文识别总耗时、候选选择耗时、最终 block 构建耗时、候选数、block 数、字符数和 `rootCache=hit|miss|bypass`。
- 第二阶段正文优化只缓存自动识别出的根元素、当前 URL 和正文规则签名；缓存命中时跳过全页面候选收集/评分，但仍按原流程重建全部 block、Markdown、文本、预览和八项评分。缓存根节点断开、URL 或规则变化、还原自动识别，以及页面真实 DOM 结构/文本/属性变化时会失效；一次失效后观察器立即断开，避免持续监听开销。包含同源 iframe 或开放 Shadow DOM 的页面旁路该缓存并继续完整识别，手动正文和编辑正文始终保持原有优先级。
- 当前选中会保存网页选区的文本和可用 Range。沉浸翻译或沉浸阅读准备选区时会把选中文字包装为可写回 block，并立即重新选择包装后的同一内容、同步更新 retained Range，不再以 `removeAllRanges()` 清空选区结束；两项功能都从当前标签的 selection context 读取文本。
- 扩展重新加载后，已经存在的标签页如果缺少 content script，侧边栏消息通道会通过 `chrome.scripting.executeScript` 自动补注入并重试，不再要求用户刷新页面。
- 沉浸阅读已支持英文词频表，中文候选会参考对应英文翻译的难度；运行级别去重已覆盖中文和英文页面。
- 悬停释义支持中文词语和英文单词的 caret 命中、形态还原和离线查词；caret 只用于寻找候选文本节点，鼠标点必须真实位于候选文字 `Range` 的非零矩形内才会触发，行首、行尾和行间空白不会回退命中最近文字。词典加载失败会允许后续重试。命中词样式使用 CSS Highlight API，不修改网页文本节点，提供无、高亮、下划线三种配置；“高亮”使用产品蓝绿色主题色的高可见度半透明背景，并保留网页原文字色。
- 自动翻译和沉浸翻译支持链接、富文本、上标、下标和引用标记的保真处理，隐藏链接地址不会作为普通文字翻译。自动翻译会保护每一个单换行和段落换行；当前正文输入直接由预览中的可见 block 按顺序重建。完整 fenced code block 会在请求前作为不可翻译对象保护，返回后原样恢复语言标记和多行代码；即使模型漏回代码占位符，也会按原始位置恢复，模型额外添加的反引号包装不会让代码退化成内联代码。翻译提示词明确禁止给普通段落新增编号、项目符号、标题或其他前缀，恢复层还会清理模型对原本无列表标记的连续普通段落新增的编号/项目符号，同时保留原文真实列表。
- 自动翻译的原始语言判断只统计代码之外的可见自然语言。fenced code、HTML `pre/code` 和 Markdown 行内代码不会参与语言识别；混合内容只有在非代码拉丁文字占可判定文字的较高比例（当前为 80% 以上）且有足够自然语言单词时，才会覆盖中文、日文或韩文判断为拉丁语言，代码占比较大不会把正文误判成英文。
- 正文提取会清理网页原文中的 citation 说明标签，例如 `**4 citations from multiple sources**[1-4]` 会保留为 `[1-4]`，`**Citation 5 from source**[5]` 会保留为 `[5]`。
- 翻译结果会清理模型重复输出的任务前言、损坏的 `WEBMIND_*` 占位符片段和引用说明噪音。自动翻译流式展示会暂存末尾尚未闭合的占位符片段，不显示 `{`、`WEBM...` 或反引号等中间字符；漏引用兜底只在响应完成后执行，不会让引用标记持续悬挂在流式末尾。
- 自动翻译短词、词组和选中内容支持更紧凑的词典式回答。首行五星只表示模型根据源语言现代通用语境自动估算的词频，五星为极常见、一星为罕见，不再输出 CET-6、GRE、IELTS 或其他考试/词表标签。词典字段使用界面语言对应的本地化名称和独立 Markdown 段落；后台会在确认进入词典模式后，将模型偶发挤在同一行的中、英、西、法、德、意字段恢复为分段结构。划词结果浮层使用隔离的 Markdown 段落、列表、粗体、代码和表格样式，不继承原网页排版。
- 自动翻译的词典式回答已收窄到真正像单词、术语或固定短语的输入；短中文句子或命令句会走普通翻译，单字/短中文词仍会锁定目标语言并要求输出真实译义。
- 设置页通用配置新增“工具使用提问上下文原始语言进行回答”：仅影响内置和自定义工具，不影响普通输入框对话；工具执行会结合 `PageContext.language` 和实际上下文文本识别具体语言，并在最终 prompt 末尾明确指定。工具提示词显式指定的回答语言优先，但模板本身的书写语言不算显式指定；自动翻译、PDF/字幕翻译和代码解释不受该配置约束。
- 设置页的界面语言与译文语言已改为同一行内并排的原生下拉框，并新增西班牙语、法语、德语和意大利语。默认仍为自动；浏览器语言自动解析、设置持久化、完整静态 UI、工具元数据、词典字段、工具回答语言、自动翻译目标、拉丁语言源文检测和沉浸阅读模型 fallback 均识别新增语言。
- 侧边栏日志、沉浸翻译、沉浸阅读、学习笔记、当前正文、框选正文、还原正文等图标已更新；自定义工具图标选择使用新版 lucide 动态图标列表，沉浸翻译/阅读使用内联 Iconify 风格图标。
- Vite 构建会将 lucide 动态图标按首字母拆成 `lucide-icons-*` chunk，避免新版 lucide 让单个 `vendor-icons` chunk 触发 500k 体积提示。
- 侧边栏临时提示和上下文错误提示显示 5 秒后自动关闭。
- MCP 工具授权已增加全局模式、30 秒无响应超时和受控的调用状态记录。后台在每次实际调用前读取设置并强制执行；侧边栏不依赖模型自行声明，而是在回答下方显示成功调用、拒绝、超时或失败的 Server / Tool 记录。

## 已知限制

- Chrome 侧边栏获得焦点后，网页文档不再拥有键盘焦点，这是浏览器行为。扩展不会在沉浸翻译/阅读准备阶段主动清空 Selection，并会保存、重新选择和更新 Range，但不能保证 Chrome 在失焦页面继续以蓝色绘制原生选区。选区真正消失后恢复到划词前的上下文；用户在选中期间手动切换上下文时，不再自动恢复旧上下文。
- 禁止复制、禁止右键、拦截 `copy` 或 `contextmenu` 通常不会影响自动翻译、沉浸翻译、沉浸阅读和普通上下文工具，因为它们读取的是 content script 可访问的 DOM 文本；但 `user-select: none` 等样式可能影响“当前选中”类功能。
- 跨域 iframe 无法被 content script 读取；同源 iframe 可以尝试读取，但实际样式注入和页面结构仍需要在真实 Chrome 中验证。
- Canvas、图片、视频画面和通过伪元素绘制的文字不属于普通 DOM 文本，当前正文识别无法直接提取；PDF 使用单独的侧边栏解析路径。
- 自动补注入只在消息接收端不存在时执行一次；浏览器内部页面、Chrome Web Store 等页面仍禁止注入。注入和首次正文识别可能产生一次性成本，但入口已经改为低优先级调度并限制扫描范围。
- 虚拟滚动和无限滚动目前只处理已经存在于 DOM 的内容，不会为了收集正文主动滚动页面。
- React/Vue 等动态页面如果在正文读取之后才完成渲染，需要重新刷新上下文或重新打开侧边栏。
- 自动正文识别只做通用 DOM 父容器选择；新闻推荐、评论、代码、表格、公式混排仍可能需要用户手动框选或逐段剔除。
- 悬停命中词样式依赖浏览器 CSS Highlight API；不支持该 API 时不绘制额外样式，但不应影响悬停释义本身。
- 正文识别规则只保存页面地址匹配和 CSS selector；selector 指向的内容仍必须存在于当前可访问 DOM 中，无法跨越浏览器禁止访问的页面或跨域 iframe。
- 手动框选依赖开放 DOM 和可见元素，跨 Shadow DOM 边界、受限页面、浏览器内部页面仍有能力边界。
- 侧边栏和 content script 的真实交互、Chrome 权限、原生选区焦点变化不能只通过 Vite 预览完全验证。
- PDF worker 构建产物较大，这是当前 PDF 处理方式的已知现象。
- MCP 的“始终允许”会跳过交互审批，因此仍应只启用可信 Server 的必要工具。即使全局授权设为允许，Server 本身仍可能访问本机或内网资源。
